Prototype notes — decisions worth arguing with

  • No trend charts on the fleet screen. /_fleet/health and /_fleet/members are point-in-time reads. A sparkline would imply history the API does not have — RFC-006 §3 rule 2 (“nothing UI-only”). The one chart here is magnitude-by-identity over numberOfRequests, which the imposter body genuinely carries.
  • Partial answers are named, never averaged. Switch Fleet → Node unreachable: the tiles that cannot be known say so, and the banner names which node is missing and how many are represented. The console never fans out and merges client-side — that would reinvent the verification plane (#147) without its cursors or gap repair.
  • Empty distinguishes “nothing here” from “cannot answer”. Try Data → Empty against each fleet state. On the request log the two are entirely different screens: an unreachable node says its log is unknown, a reachable one says it recorded nothing.
  • The request log's scope selector never collapses. Per-node is the fact that screen has to keep in front of the reader, so the node in scope and the count of nodes not represented sit above the table permanently, not in a dismissible banner. The merged journal (#147) drops the label and keeps the shape.
  • Match diagnostics are the reason to open the log. An unmatched request lists every stub that was tried and the predicate that rejected it — that is what an operator is actually looking for when a system under test gets a 404.
  • Row r-8812 is hostile on purpose. Its path carries a <script> tag and its user-agent an onerror attribute. Recorded payloads are the most attacker-influenced surface in the console, so they render as text in a <pre>, never as markup — if you ever see that row execute, the escaping regressed.
  • Status is triple-encoded — glyph shape (● ▲ ■ ○), colour, and word. Green↔red sit ~ΔE 5 apart under deutanopia, so colour alone would fail; the validator confirmed that rather than my eye. Light-mode amber was darkened to #8A5A00 after it measured 2.24:1 against white.
  • Viewer hides write affordances but that is UX only. RFC-006 §3 rule 3: the API re-checks every call. A hidden control is never the only guard.
  • Every identifier is monospace — ports, revisions, op-ids, node names. These are values an operator pastes into curl, and rift-tui is the interaction precedent RFC-006 §4 names deliberately.
  • Cross-tenant is 404, not 403. Not shown on these two screens, but it lands in #190: a tenant you are not bound to must be indistinguishable from one that does not exist (RFC-002 §8.4).
  • Desktop only (RFC-006 §10). The narrow-window collapse here is prototype convenience, not a mobile layout.
